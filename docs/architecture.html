Engine, host and editor

The native engine interprets Lisp and binds browser/engine capabilities. Lisp applications decide how to use those capabilities. The editor is an application with authority to inspect a separate embedded application; the game receives no editor capabilities or source namespace.

Interpreter

lisp.js reads forms and evaluates lexical functions with a shared caller instruction budget. metadata.js retains generic annotations and source locations; state-values.js validates bounded JSON data. The interpreter does not interpret slider annotations, generator declarations, filename extensions, previews, file panes or project formats. Collection operations are persistent; execution limits apply to native collection callbacks too.

Application host

module-loader.js resolves explicit paths. application.js provides one stageApplication, updateApplication and drawApplication path to both the editor and standalone browser host. Scene transitions are staged against candidate state; lifecycle cleanup and initialization precede validation, and failed candidates never replace the active application. engine-services.js supplies pointer, keyboard, drawing, audio and resource capabilities. audio-output.js shares browser playback instead of duplicating AudioContext setup.

Graphics

defdraw render builds ordered commands once per frame. Nested pixels blocks capture per-invocation values and compile material functions for the GPU compositor. There are no legacy scene/image shader texture passes. Native drawing/GPU code stays native for predictable throughput. Bindings are cached per draw list; pixel source/pipelines are bounded caches. PNG export renders the full composition and correctly handles GPU row alignment. Feedback canvases keep two GPU history textures. Passes read the previous texture and capture the current composition into the other; the host publishes the new history only after the whole composition succeeds. This preserves private history across nested and duplicate views. Preview scaling does not change logical buffer dimensions. Snapshot/paused passes are read-only; inactive history entries are bounded and destroyed.

Editable editor policy

editor/policy/files.lisp owns file roles, tabs, tab fitting, dialogs and command filtering. inspector.lisp interprets field and hook annotations. workflows.lisp chooses file views, generator placement, inspector edits, settings, move/delete state updates and backup plans. shortcuts.lisp owns key mappings and menu/focus decisions. docking.lisp owns split-tree edits, floating/resizing rules, drop previews and dwell timing. These pure functions return data and state patches. Native bindings apply patches and perform browser effects after successful staging. They invoke the active editor's definitions, including edits made through the command palette; Node tools use the bundled policy fallback. Templates and examples are ordinary Lisp project files.

Native editor services

Keep native text input/IME/clipboard/selection, glyph layout, image/audio decoding, HTTP resource refresh, accessibility mirrors, file downloads and GPU operations in JavaScript. File-tree indexing and tab layout queries are cached and invalidate on input/definition changes. File/folder plans and naming rules are Lisp; token scanning, source rewriting and atomic application remain native to preserve source text. Component measurement and split-tree arrangement remain native hot paths. The editor and game share engine drawing/audio services. Lisp owns presentation and policy. app.js coordinates browser services; it is not the interpreter and is excluded from exported applications.

Performance and recovery boundaries

Run node tests/benchmark-editor-policy.mjs to compare native layout with an equivalent label-column Lisp prototype and exercise 256-tab fitting. The prototype covers only that subset; production measurement also handles nesting, flexible space, padding and scrolling. Its interpreter overhead is why measurement stays native. Dock drag policy runs only during interaction, while tab results are reused on unchanged frames. Collections are persistent; callers replace values rather than mutating nested cached inputs.

F2 is reserved by the host as an emergency recovery key. Recovery draws the bundled editor and dispatches its bundled shortcut policy even if project policy throws. The original project files remain available for repair. Runtime isolation, bounded input validation, rollback and GPU/browser resources stay native; game code receives no editor capabilities.

Current project contract

Version 1 projects contain files, resources, editor state, applicationState and recovery. Tabs and folders are vectors. Projects are validated without seed merging, historical migrations or filename aliases. Unsupported prototype formats are rejected. Local storage uses aioli.project. An export bundles only engine dependencies, game source and ordinary assets; generated main.lisp imports game.lisp and starts fresh application state.

Checks

Run npm test and npm run format:check. Browser checks verify precise GPU colors and alpha, structured inspector edits, editable policy, private application state, playback, file operations, reload/recovery and offline export. Tests for obsolete migrations were removed alongside their implementation; current-format validation and round-trip checks replace them.
