Engine, host and editor

The native engine interprets Lisp and binds browser/engine capabilities. Lisp applications decide how to use those capabilities. The editor is an application with authority to inspect a separate embedded application; the game receives no editor capabilities or source namespace.

Interpreter

lisp.js reads forms and evaluates lexical functions with a shared caller instruction budget. metadata.js retains generic annotations and source locations; state-values.js validates bounded JSON data. The interpreter does not interpret slider annotations, generator declarations, filename extensions, previews, file panes or project formats. Collection operations are persistent; execution limits apply to native collection callbacks too.

Application host

module-loader.js resolves explicit paths. application.js provides one stageApplication, updateApplication and drawApplication path to both the editor and standalone browser host. Scene transitions are staged against candidate state; lifecycle cleanup and initialization precede validation, and failed candidates never replace the active application. engine-services.js supplies pointer, keyboard, drawing, audio and resource capabilities. audio-output.js shares browser playback instead of duplicating AudioContext setup.

Graphics

defdraw render builds ordered commands once per frame. Nested pixels blocks capture per-invocation values and compile material functions for the GPU compositor. There are no legacy scene/image shader texture passes. Native drawing/GPU code stays native for predictable throughput. Bindings are cached per draw list; pixel source/pipelines are bounded caches. PNG export renders the full composition and correctly handles GPU row alignment.

Editable editor policy

editor/policy/files.lisp owns file roles, tabs, dialogs, command filtering and generator selection. editor/policy/inspector.lisp owns field inference, bounds, choices, normalization and preview annotation interpretation. The JS adapter invokes the editor's current definitions; a bundled fallback serves Node tests/tools. Editing policy changes behavior through ordinary evaluation. editor/templates contains normal project files used as starter text, and examples contains normal scenes, generators and commands rather than JS source strings.

Native editor services

Keep native text input/IME/clipboard/selection, glyph layout, image/audio decoding, HTTP resource refresh, accessibility mirrors, file downloads and GPU operations in JavaScript. File-tree indexing is cached; source/file rewrite planning remains native to preserve readable source and atomic operations efficiently. Lisp owns presentation and policy. app.js coordinates browser services; it is not the interpreter and is excluded from exported applications.

Current project contract

Version 1 projects contain files, resources, editor state, applicationState and recovery. Tabs and folders are vectors. Projects are validated without seed merging, historical migrations or filename aliases. Unsupported prototype formats are rejected. Local storage uses aioli.project. An export bundles only engine dependencies, game source and ordinary assets; generated main.lisp imports game.lisp and starts fresh application state.

Checks

Run npm test and npm run format:check. Browser checks verify precise GPU colors and alpha, structured inspector edits, editable policy, private application state, playback, file operations, reload/recovery and offline export. Tests for obsolete migrations were removed alongside their implementation; current-format validation and round-trip checks replace them.
