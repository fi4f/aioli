Editor guide

The workshop is your program too.

Start with the game and its source. Open tools when you need them. Change the editor using the same workflow as changing gameplay.

Project settings

Desktop pane titles can be dragged into floating panels or docked at any workspace edge. Pane edges and shared dividers resize panes; Escape cancels dragging. Drop onto a docked pane's side to split its area. Clicking floating content brings its pane to the top. Panes minimize into the bottom bar with a down chevron and restore with an up chevron, and View → Reset layout restores defaults. See UI components to build reusable editor controls and panes in Lisp.

Choose Project → Settings… to change the project name and canvas size. The name becomes the exported HTML page title. Apply saves changes together; Cancel discards them. The canvas accepts custom width and height or presets of 320 × 240, 640 × 360, and 512 × 512. Each dimension must be a whole number from 16 to 2048. Apply updates the logical canvas, drawing coordinates, shader dimensions, pointer coordinates, and PNG export. The game renders into a pixel buffer at that exact resolution; preview and exported HTML enlarge it without smoothing and preserve its aspect ratio with letterboxing. JSON saves retain the settings; a new project starts at 320 × 240. Changing resolution does not rewrite coordinates in existing scene code. 

(defdraw render []
  (background "#272822")
  (pixels [p time]
    (fill "#66d9ef")
    (circle [(/ width 2) (/ height 2)] 40))
  (fill "#f8f8f2")
  (rect [0 0] [(canvas-width) 2]))

The workspace

View → Code shows or hides source. View → Inspector views and edits live game/scene state. Project → Run / Evaluate evaluates the current project. On a narrow screen, hide Code to see the game at a useful size.

Source tabs initially contain main.lisp and game.lisp. Clicking any source in the Files pane opens a tab, or selects its existing tab. Each buffer retains its cursor, selection, scroll position and undo history while switching. Close a tab with its x; the source remains in the project. Overflow arrows browse tabs that do not fit. A star marks a draft that differs from the accepted source. The open tab list and selected tab are saved with the project.

Clicking an image opens a preview with drag-to-pan, wheel zoom, +/- controls, Fit and 1:1. Clicking audio opens a waveform with Play/Pause, Stop and click/drag seeking. Closing the preview (or Escape) stops audio playback. See asset previews.

The root main.lisp and editor/ui/components.lisp import the editor modules. editor/ui/ holds reusable controls; editor/ holds complete panes and widgets. Open these files from the explorer and edit them live. Browser edits belong to the saved project rather than changing the repository on disk.

Edit the theme

editor/theme.lisp is an ordinary editor module imported by editor/state.lisp. It owns all editor colors: charcoal surfaces, a cyan accent, Monokai pink keywords, purple numbers and yellow strings. Selection, hover, disabled text, errors, checkerboards, audio playheads, icons and inline hook buttons use the same named palette. Game and generator artwork keep their own colors.

Change the file and press Ctrl+Enter, or enable automatic re-evaluation. Theme declarations use set! so edits replace saved values immediately; changing an init! default would preserve the previous saved color. These constants belong to editor state and are unavailable to the embedded game. Custom themes remain in saved projects and survive reload and recovery-shell creation. 

; editor/theme.lisp
(set! :ui-bg "#1e1f1c")
(set! :ui-panel "#272822")
(set! :ui-accent "#66d9ef")
(set! :ui-syntax-keyword "#f92672")
(set! :ui-code-line-height 24)

Edit the existing declarations rather than replacing the whole theme with this excerpt. Widgets read values with (get :ui-accent), for example.

Constants Use
ui-bg, ui-panel, ui-shadow, ui-border Workspace surfaces and separators.
ui-text, ui-muted, ui-disabled, ui-active-text, ui-line-number Text and line numbers.
ui-accent, ui-button, ui-hover, ui-selection, ui-drop-target Icons, controls, selection and file dragging.
ui-hook-bg, ui-hook-hover, ui-slider-track, ui-error, ui-playhead, ui-checker-dark, ui-checker-light Hook previews, sliders, diagnostics and resource previews.
ui-syntax-comment, ui-syntax-string, ui-syntax-keyword, ui-syntax-number, ui-syntax-delimiter Source highlighting.
ui-files-width (280), ui-inspector-width (264), ui-collapsed-width (40), ui-code-fraction (0.42), ui-narrow-width (850) Pane sizes and responsive layout. Expanded widths should be at least 240, collapsed width at least 40, and code fraction between 0 and 1.
ui-icon-size (16), ui-file-row-height (26), ui-field-height (56), ui-code-line-height (21), ui-code-gutter (40) Shared logical-pixel spacing. Use icons 16–20, file rows at least 24, inspector fields at least 48, code lines at least 20 and gutter at least 24. Painting and pointer mapping use the same code metrics; glyphs remain fixed 8 × 18 bitmap cells.

Older projects receive the theme file once and unchanged stock editor components upgrade automatically. Customized components and existing theme files are preserved. The static documentation mirrors the default palette; editing a project theme affects that project.

Play Kaboom

Expand examples/ in Files and click the play button beside kaboom.scene.lisp. Click the preview to direct keyboard input to the game; F4 enlarges it and restores your previous editor layout when toggled again. W/S or Up/Down walk, A/D strafe, Left/Right or Q/E turn, Space fires, and R restarts. Defeat three monsters with two hits each, then reach the green gate at the southeast corner of the minimap. Contact with monsters costs health; walls block movement and shots.

The entire example is ordinary Lisp: GPU grid raycasting traces every canvas column, shades brickwork, casts perspective floor and ceiling textures, and depth-tests monster pixels. The default 320-wide canvas gives 320 single-pixel columns; larger canvases add detail, and wider aspect ratios increase the field of view. Walls and grounded monster sprites share the same projection. Movement, collisions and shooting stay on the CPU. The pistol has walking bob and recoil, without imported art. Edit its annotated movement settings in the scene inspector, inspect the pistol and minimap defdraw hooks, or listen to its procedural defsound hooks. To launch it as your application, put (start-scene "examples/kaboom.scene.lisp") in game.lisp; HTML export then bundles it with the runtime. Existing saves receive the example once, preserving custom copies and later deletions.

Play Neon Orbits

In a new project, expand examples/ in Files and play raytrace.scene.lisp. This asset-free pixel shader traces three animated spheres, a checkerboard floor, reflected rays and soft shadows. Click Game, then use A/D or Left/Right to orbit, W/S or Up/Down to zoom, Space to freeze/resume, and R to reset the camera. F4 enlarges Game. Inspector controls the camera height, lighting and reflection strength. Existing projects can add the source through File → Open file. Set (start-scene "examples/raytrace.scene.lisp") in game.lisp to use it as the application entry; HTML export runs it offline.

Play Pocket Peaks

Play examples/platformer.scene.lisp from Files in a new project. This original side-scrolling platformer has an orange courier, coins, gold coin blocks, patrolling slimes, pits, a checkpoint and a finish flag. A/D or arrows move, Space/W/Up jump, X runs, and R restarts. Release jump early for a shorter hop. Stomp slimes from above; side contact costs a life. The checkpoint preserves collected coins and defeated enemies after a fall. Collect all 15 coins, or simply reach the finish. Inspector exposes speed, jump strength and gravity. Existing projects can add the source through File → Open file. Use (start-scene "examples/platformer.scene.lisp") in game.lisp as the application entry for offline HTML export.

The menu bar

The workspace has five menus: File, Project, View, Edit, About. Dropdowns group related actions and show checked pane visibility, disabled actions and shortcut hints.

  • File: new project, new/open/save individual files, open/save project JSON, import resources, download/rename/delete selected files, export the game PNG. Entry files cannot be renamed or deleted.
  • Project: run/evaluate, play/pause, reset state, toggle automatic re-evaluation, adopt the latest editor while in recovery.
  • View: code/files panes, scene inspector, image/audio/text generator inspectors, command palette, compiled WGSL, recovery shell; return to the project editor while recovering.
  • Edit: undo/redo, cut/copy/paste, select all. Undo history belongs to each source buffer and holds up to 100 edits. Read-only buffers disable mutations, and copy/cut require a selection. Menu clipboard commands use browser clipboard permission; ordinary keyboard clipboard shortcuts still work with native source input.
  • About: application information, documentation, language guide.

Click outside a dropdown or press Escape to dismiss it. Hover another menu heading to switch. Alt+F/P/V/E/A opens a menu; Left/Right switches domains, Up/Down selects an enabled item, and Enter activates it. Ctrl/Cmd+S downloads the project JSON, Ctrl/Cmd+O opens a project, Ctrl/Cmd+Enter evaluates, and Ctrl/Cmd+Shift+P opens the palette.

Typing and live evaluation

Click inside the source pane to focus it. Standard text selection, arrow navigation, clipboard shortcuts, and browser input composition use a hidden textarea. Source text, syntax highlighting, selections, and the blinking caret are painted by the Lisp source widget on the WebGPU canvas. Unsupported glyphs currently display as ?.

Wheel scrolls vertically; Shift + wheel scrolls horizontally. Tab inserts two spaces. Opening quotes and incomplete expressions remain visible while you type.

With Project → Automatic re-evaluation enabled, a 500 ms pause in typing triggers evaluation. Press Ctrl/Cmd + Enter or Run to evaluate immediately. All source buffers are checked together. Valid changes replace the working runtime and shader; failed changes leave them running and show an error in the status bar. Click an error to open its full diagnostic text.

A visible unfinished string is valid editor text, but it is not yet valid code. Finish its quote before evaluation can succeed.

Playing the example

Click the game view before using A/D or Left/Right to move. Space, Up, or W jumps. The Pause control freezes game time and gameplay; the editor remains interactive. Source typing never drives game input.

The preview fills the available pane while preserving its aspect ratio. Click Focus / F4 or press F4 to hide the other panes and focus gameplay. Toggle again or press Escape to restore the previous layout, tabs and inspector position. The same toggle is available under View / Focus preview.

File / New project starts the default application in examples/garden.scene.lisp. Open file adds an individual source or asset to the project; Save file downloads the current source draft or asset. Project open/save remain separate. Drag files onto folders in Files to move them; drop on the Files header to move to the root. Moves update relative imports and literal paths, preserve tabs, and reject occupied destinations.

Scene inspector and playback

View → Inspector displays fields belonging to the currently running scene, including its imports and fields created by its hooks. If no scene is active, it inspects game.lisp instead. Values left in shared state by earlier scenes and unrelated game.lisp fields are hidden. It supports sliders, choices, booleans, colors, editable text and structured JSON values. Optional init! annotations supply labels, limits, steps, or choices: 

(init! :radius 20 ["Radius" 5 80 0.5])
(init! :mode "round" ["Mode" ["round" "square"]])
(init! :enabled true ["Enabled"])

Values update the running scene immediately. Shared game state retains earlier values for transitions; inspector visibility is scoped to the active scene. Editor state remains separate. Unannotated fields receive inferred controls; fields created by hooks appear too. Use the mouse wheel or draggable scrollbar for more fields. Arrows at the top and bottom indicate hidden content. Text edits use Apply; colors open a picker.

A controller marks game.lisp, gears mark generators, and movie clappers mark scenes. Click a scene's play button to switch the preview; main.lisp's run button executes the whole project like Ctrl+Enter. Click game.lisp's play button to restart with fresh state. Failed scenes keep the last working preview. Browse the editable scenes in examples/; playback never rewrites source.

Creating files and scrolling the tree

File → New file offers None, Script, Scene, Command and Generator. Script adds .lisp; Scene, Command and Generator add their role suffix. Existing Lisp suffixes are replaced rather than doubled. None keeps the exact name and creates an empty buffer. Generators offer Image, Audio and Text starters. The dialog shows the final filename before creation.

The Files pane scrolls vertically with the wheel and horizontally with Shift+wheel or a trackpad's horizontal gesture. Drag either scrollbar when its content overflows. Long names and deep indentation scroll together; folder expansion, selection and scroll position survive collapsing and restoring the pane.

Text generators

Generators open in a floating inspector that can dock beside or within another pane. Its chevron collapses the inspector and X closes it. Next keeps the current placement when switching generators; Code opens the selected generator in the main Code pane. The View menu groups Files, Code, Game, Inspector and Generators visibility together, followed by layout controls, tools and recovery actions. Game visibility is controlled through View → Game.

Text recipes declare (generator :text "Title" "levels/generated.csv") and return a string from generate-text. Annotated fields drive the preview. Generate explicitly reruns the hook, Keep stores its UTF-8 output, and Download stores and downloads it. Click a kept text resource to inspect it in a read-only source view. See the text generator guide for examples and limits.

Folders and evaluation

Right-click a file, folder or blank area in Files to create a folder. Folder menus also offer Rename folder, Move folder and Delete folder, with a count of contained files. Enter a full project path to rename or move a folder, or drag it onto another folder or the Project files header. Empty folders persist in project saves. Moves update child paths, relative imports, literal asset/scene references and open tabs together; destinations are never overwritten. Delete removes all descendants. If a required import or active scene would become invalid, deletion keeps the original folder and reports the reference that must be changed first. These actions change project data, rather than directories on disk.

Project / Automatic re-evaluation controls whether source edits execute after the usual debounce. It is enabled by default and saved with the project. Turning it off cancels a pending evaluation; Ctrl+Enter, Run / Evaluate and the main.lisp run button still execute explicitly. Turning it back on evaluates pending edits.

Previewing individual hooks

Declare a composable drawing function with defdraw or a sound effect with defsound. A Preview draw or Preview sound button appears directly above each declaration in the code editor. These UI rows do not change the source or its line numbers. Click a button to inspect that hook, then Code to return to the source. Drawing previews run the selected function on a fresh canvas; sound previews offer waveform seeking, play/pause, stop and a one-second forward button. Edit preview arguments as a JSON array and click Preview. Inspection uses a private state copy and leaves gameplay running independently. See hook syntax and examples.

Extending the editor

Start with a small edit in editor/workspace.lisp. Add this inside its existing editor function: 

(scope
  (fill "#bbd6a6")
  (circle [400 24] 5)
  (text [416 16] "My workshop"))

For an action, use a function from the widget library:

(when (ui-button :reset-moon "Reset moon" [24 100] [140 32] false)
  (game-set! :moon 20))

Use unique IDs and screen-space bounds. Place controls after the pane/background they should appear above: drawing order is painter order. Change ui-button in ui to change the appearance or interaction of every button. Change token-color to customize source colors.

The theme is initialized with keys such as :ui-bg, :ui-panel, :ui-text, :ui-muted, and :ui-accent. To change an existing theme without resetting state, evaluate a set! form rather than only modifying its init! default.

Recovery

Press F2 if an editor edit hides the controls or breaks its frame. The stock editor opens in recovery mode with your editor source available. Your draft remains intact. Repair it and evaluate again to return to your custom editor.

An invalid saved project also opens a recovery shell on startup. Gameplay and audio errors are reported separately from editor drawing errors. Fix the corresponding source and evaluate to resume. Escape closes menus/tools and releases gameplay keys.

Saving and exporting

Menu action Result
File → Export application HTML Download one offline HTML file containing the runtime, game sources and assets.
File → Save project Download editable JSON containing source drafts and state.
File → Open project Validate and load project JSON; rejected imports retain the current working program.
File → Export game PNG Download a 320 × 240 PNG of the game view.
Project → Reset state Rerun the current source with fresh initial values.
View → Compiled WGSL Inspect the compiled scene as a read-only source buffer.
About → Documentation Open the language, API, and editor documentation.

The browser also stores accepted source and shared state in local storage. Invalid drafts do not overwrite accepted source there. Storage belongs to the browser origin: moving from localhost to a hosted site does not automatically move projects. Save/Open JSON transfers projects between hosts. Only current-format projects are loaded.
