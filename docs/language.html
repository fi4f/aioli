Language

Expressions all the way down.

Gameplay, audio recipes, and editor functions share one Lisp. Pixel shaders use a checked subset with the same reader and syntax.

Syntax and values

; A semicolon starts a comment through the end of the line.
(+ 2 3)                 ; a call: operator first, then arguments
[20 40]                 ; a vector
"Hello"                 ; a string
"Say \"hello\"\n"        ; JSON-style string escapes
:moon                    ; a keyword, evaluated as the string "moon"
true false nil           ; CPU booleans and null

Numbers may be integers, decimals, or scientific notation: 12, -0.5, .25, 1e2. Evaluated vectors contain evaluated items, so [(+ 10 5) 20] becomes a pair of numbers.

Symbols refer to names in the current environment. Keywords are convenient string keys, so :moon and "moon" identify the same state entry. There is no quote/list literal form, macro system, or module syntax yet. Empty () is not a valid expression; empty [] is a valid CPU vector.

The source view shows incomplete expressions while you type, including an unfinished string. Evaluation still requires balanced syntax and a closing quote. A rejected edit leaves the last working program running.

Functions and local bindings

(defn double [value]
  (* value 2))

(defn move-player [dt]
  (let [distance (* (get :speed) dt)
        next-x (+ (get :x) distance)]
    (set! :x next-x)))

defn defines or replaces a function. Its argument vector lists names, and a call must supply exactly that many values. Body expressions run in order; the final expression is the return value. Functions capture their lexical environment.

let introduces local bindings in name/value pairs. Bindings are evaluated left to right, so later values may use earlier names. do runs several expressions where a single expression is expected. There is no general local assignment form; set! writes shared state.

Shared state

(init! :speed 75)        ; assign only if the key is absent
(init! :x 160)
(get :x)                 ; read; missing keys are an error
(set! :x 200)            ; write and return the value
(set! :accent "#bbd6a6")

Shared state connects gameplay, procedural controls, and shaders. It stores finite numbers, strings, booleans, null, vectors and maps. Functions cannot be persisted. init! avoids resetting existing values on a hot edit. Editing an initialization value will therefore affect a fresh state, not an already initialized one: use set! or Project → Reset state to change that value immediately.

A pixel block reads state with (get :key), capturing the value as a uniform. Finite numbers, numeric vectors and hex colors are supported; convert booleans to numbers outside the block.

Control flow and repetition

(if (> (get :x) 300)
  (set! :x 300)
  (set! :x (+ (get :x) 1)))

(when (and (key? " ") (>= (get :y) 190))
  (set! :vy -130)
  (play-sound))

(repeat 4 i
  (fill "#bbd6a6")
  (circle [(+ 20 (* i 16)) 40] 5))
Form Behavior
(if condition yes no) Evaluate one branch. The false branch is optional and defaults to nil.
(when condition body...) Run the body only when the condition is truthy.
(and expr...), (or expr...) Short circuit and return a boolean.
(not value) Negate truthiness.
(repeat count index body...) Bind a zero-based index for each iteration. Count must be an integer from 0 to 64.
(scope body...) Temporarily change drawing state, restoring it afterward while retaining drawn pixels.

CPU truthiness follows JavaScript values: false, nil, zero, and an empty string are falsey; vectors are truthy, including an empty vector. Comparisons are = < > <= >=; = checks strict equality and does not perform structural vector equality.

Math and collections

CPU API Meaning
+ - * / Numeric arithmetic. Unary - negates; use two or more operands for division.
sin cos abs floor round Standard numeric functions; angles are radians.
min max Minimum or maximum of numeric arguments.
(clamp value low high) Restrict a number to an interval.
(mod value divisor) Wrapped remainder; use a positive divisor.
(str values...) Concatenate string representations.
(count collection) Length of a vector or string.
(nth collection index) Zero-based element; an out-of-bounds index is an error.

CPU arithmetic checks finite numbers and rejects non-finite results, including division by zero. Vector arithmetic is supported in shaders, not in these CPU numeric functions.

Structured state and collections

(init! :player (map :x 160 :y 120) ["Player"])
(set! :player (assoc (get :player) :x 200))
(init! :items ["key" "lamp"] ["Items"])
(set! :items (conj (get :items) "coin"))
(mapv (fn [x] (* x 2)) [1 2 3])
(filter (fn [x] (> x 1)) [1 2 3])
(reduce (fn [sum x] (+ sum x)) 0 [1 2 3])

map takes key/value pairs. lookup reads a vector index or map key, with an optional fallback (nil by default). assoc and conj return new collections. keys, values, contains?, slice, concat, distinct and sort support collection processing. Equality compares collection contents. distinct uses identity for collection entries and value equality for primitives. fn creates a lexical anonymous function; mapv/filter callbacks receive one item, reduce receives accumulator/item, and optional sort comparators receive two items and return a number.

range returns indices from zero to count minus one, with count 0–10000. Collection operations share the active interpreter budget, including calls to helpers from another application scope. State values are bounded JSON data: at most 10,000 nodes and 32 nested levels per value, with finite numbers and safe property keys. json-read validates JSON; json-write serializes valid data.

Declaration metadata

(definitions) returns records with name, kind, parameters, annotation, path and line. (state-metadata) returns key, default value, computed flag, annotation, path and line. Annotations remain uninterpreted in the engine. Editor Lisp chooses sliders, choices, previews and labels. Literal defaults preserve their declared values; computed defaults expose their evaluated/preserved value without rerunning initialization. Imported helpers retain their defining source positions.

Drawing and nested pixel effects

(defdraw plasma [speed]
  ["Plasma" [2] [320 240]]
  (pixels [p time]
    (rgb (+ 0.5 (* 0.5 (sin (+ (* p.x 0.02) (* time speed)))))
         0.2
         0.6)))

(defdraw render []
  (plasma 2)
  (fill "#f8f8f2")
  (text [12 12] "Shapes, text and procedural pixels"))

defdraw render [] is the primary render hook. Every drawable is an ordinary callable Lisp function and can call imported drawables, use state, loops and conditions, and compose shapes, text and pixel effects. The CPU builds this ordered stream once per frame; the GPU renders its coverage and evaluates nested pixel effects. Shapes after a pixel block appear above it. Use scope around reusable components to restore drawing settings.

(pixels [p time] ...) is the GPU boundary inside a drawable. Its body can return a color expression (scalar grayscale, RGB, RGBA, or hex color) or use shader drawing commands. It covers the drawable's logical canvas, with the surrounding translation, scale, clipping, opacity and blend mode applied. Transparent pixels preserve earlier drawing; a color result replaces the block's own accumulated color. The default is transparent until painted. Outer fill colors do not tint the pixel result.

p, p.x and p.y are local pixel coordinates; time is elapsed game/scene time. width, height, (canvas-width) and (canvas-height) describe the logical drawing canvas, independent of preview scale or DPI. These names are reserved inside a pixel block. Drawable arguments and outer lexical numeric/color values are captured as uniforms. Numeric vectors of 2–4 components and their .x/.y/.z/.w components are supported. (get :key) reads a state value once per invocation; State changes update uniforms without recompiling the program. Supported captures are finite numbers, hex colors, and numeric vectors; convert booleans to numbers outside the block when needed.

Keep gameplay, browser access, sound, mutation, conditions and calls to ordinary Lisp functions outside pixels. None of those execute per pixel. Compose pixel effects by calling their enclosing defdraw functions from render. Pixel bodies use the shader subset below. Rendering uses defdraw render []; there is no separate CPU or legacy pixel render hook.

Shader bodies support drawing commands, let, scope, and repeat. Repetition requires a literal count and expands during compilation. They do not support CPU defn calls, if, when, state mutation, text, or editor input.

Shader expressions include + - * / sin cos abs floor fract length noise min max pow mod clamp mix step smoothstep vec2 vec3 rgb rgba, (position), and (get :key). Two-, three-, and four-component numeric vectors are supported. Vector lengths must match; arithmetic can combine a scalar and a vector. Other functions require compatible WGSL argument types: for example, use (pow [0.2 0.4 0.6] [2 2 2]), not a vector and scalar exponent.

noise is currently a deterministic hash of a 2D position producing a value in [0, 1); it is not smooth interpolated noise. See the shader math reference for signatures and examples.

Ordinary drawing and nested pixel bodies share syntax and drawing concepts, but their supported forms differ. A WebGPU validation error keeps the previous shader active. CPU functions cannot yet be called from shaders.
