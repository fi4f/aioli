Language

Expressions all the way down.

Gameplay, audio recipes, and editor functions share one Lisp. Pixel shaders use a checked subset with the same reader and syntax.

Syntax and values

; A semicolon starts a comment through the end of the line.
(+ 2 3)                 ; a call: operator first, then arguments
[20 40]                 ; a vector
"Hello"                 ; a string
"Say \"hello\"\n"        ; JSON-style string escapes
:moon                    ; a keyword, evaluated as the string "moon"
true false nil           ; CPU booleans and null

Numbers may be integers, decimals, or scientific notation: 12, -0.5, .25, 1e2. Evaluated vectors contain evaluated items, so [(+ 10 5) 20] becomes a pair of numbers.

Symbols refer to names in the current environment. Keywords are convenient string keys, so :moon and "moon" identify the same state entry. There is no quote/list literal form, macro system, or module syntax yet. Empty () is not a valid expression; empty [] is a valid CPU vector.

The source view shows incomplete expressions while you type, including an unfinished string. Evaluation still requires balanced syntax and a closing quote. A rejected edit leaves the last working program running.

Functions and local bindings

(defn double [value]
  (* value 2))

(defn move-player [dt]
  (let [distance (* (get :speed) dt)
        next-x (+ (get :x) distance)]
    (set! :x next-x)))

defn defines or replaces a function. Its argument vector lists names, and a call must supply exactly that many values. Body expressions run in order; the final expression is the return value. Functions capture their lexical environment.

let introduces local bindings in name/value pairs. Bindings are evaluated left to right, so later values may use earlier names. do runs several expressions where a single expression is expected. There is no general local assignment form; set! writes shared state.

Shared state

(init! :speed 75)        ; assign only if the key is absent
(init! :x 160)
(get :x)                 ; read; missing keys are an error
(set! :x 200)            ; write and return the value
(set! :accent "#bbd6a6")

Shared state connects gameplay, procedural controls, and shaders. It stores finite numbers, strings, and booleans, rather than vectors or functions. init! avoids resetting existing values on a hot edit. Editing an initialization value will therefore affect a fresh state, not an already initialized one: use set! or Project → Reset state to change that value immediately.

A shader reads shared state with (param :key). Its parameters must already exist when the scene compiles. Numeric values and booleans become scalar uniforms; color strings become RGBA uniforms. Other strings are not shader parameters.

Control flow and repetition

(if (> (get :x) 300)
  (set! :x 300)
  (set! :x (+ (get :x) 1)))

(when (and (key? " ") (>= (get :y) 190))
  (set! :vy -130)
  (play-sound))

(repeat 4 i
  (fill "#bbd6a6")
  (circle [(+ 20 (* i 16)) 40] 5))
Form Behavior
(if condition yes no) Evaluate one branch. The false branch is optional and defaults to nil.
(when condition body...) Run the body only when the condition is truthy.
(and expr...), (or expr...) Short circuit and return a boolean.
(not value) Negate truthiness.
(repeat count index body...) Bind a zero-based index for each iteration. Count must be an integer from 0 to 64.
(scope body...) Temporarily change drawing state, restoring it afterward while retaining drawn pixels.

CPU truthiness follows JavaScript values: false, nil, zero, and an empty string are falsey; vectors are truthy, including an empty vector. Comparisons are = < > <= >=; = checks strict equality and does not perform structural vector equality.

Math and collections

CPU API Meaning
+ - * / Numeric arithmetic. Unary - negates; use two or more operands for division.
sin cos abs floor round Standard numeric functions; angles are radians.
min max Minimum or maximum of numeric arguments.
(clamp value low high) Restrict a number to an interval.
(mod value divisor) Wrapped remainder; use a positive divisor.
(str values...) Concatenate string representations.
(count collection) Length of a vector or string.
(nth collection index) Zero-based element; an out-of-bounds index is an error.

CPU arithmetic checks finite numbers and rejects non-finite results, including division by zero. Vector arithmetic is supported in shaders, not in these CPU numeric functions.

The shader subset

(defpixel example [p time]
  (background "#101613")
  (let [pulse (+ 20 (* 5 (sin time)))]
    (fill (rgb 0.7 0.8 0.6))
    (circle [160 120] pulse)))

A scene and its imports contain exactly one defpixel hook with arguments [p time]. The compiler translates only that hook to WGSL. Ordinary CPU Lisp forms may live alongside it; see imports and scene hooks. Each invocation evaluates one pixel, accumulating color as drawing commands run. p, p.x, and p.y read the current transformed pixel position; time is seconds; width and height are 320 and 240.

Shader bodies support drawing commands, let, scope, and repeat. Repetition requires a literal count and expands during compilation. They do not support CPU defn calls, if, when, state mutation, text, or editor input.

Shader expressions include + - * / sin cos abs floor fract length noise min max pow mod clamp mix step smoothstep vec2 vec3 rgb rgba, (position), and (param :key). Two-, three-, and four-component numeric vectors are supported. Vector lengths must match; arithmetic can combine a scalar and a vector. Other functions require compatible WGSL argument types: for example, use (pow [0.2 0.4 0.6] [2 2 2]), not a vector and scalar exponent.

noise is currently a deterministic hash of a 2D position producing a value in [0, 1); it is not smooth interpolated noise. See the shader math reference for signatures and examples.

The CPU and shader contexts share syntax and drawing concepts, but their supported forms differ. A WebGPU validation error keeps the previous shader active. CPU functions cannot yet be called from shaders.
