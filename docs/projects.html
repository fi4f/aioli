Projects and tools

More files. More ways to make things.

A project contains named Lisp files, imported assets, generated images and sounds, and shared state. The file pane and tool windows are live Lisp widgets in editor/, composed from ui/ controls.

File explorer

Use View → Files pane to dock the folder tree beside code and the game. Click a folder row to expand or collapse it. Nesting and expansion are saved with the project. Icons distinguish folders, code, images, audio and generic assets. Click a source to open its code tab; clicking an image or audio asset opens its preview window. Scroll with the mouse wheel or by dragging the scrollbar. Collapsed descendants consume no scroll space. On narrow screens, opening a source returns to the code pane.

Right-click a file, folder or empty tree area for file actions. Shift+F10 opens the selected file's menu. New file, Import resource, Download, Rename and Delete are also under File. New file and Rename open a filename dialog. Use slash-separated paths such as lib/math.lisp. New file on a folder starts inside that folder; on a file, it starts beside that file. Create starts with a commented module. Import accepts local Lisp, image and audio files under assets/ and never overwrites existing paths. Rename does not rewrite imports: update references yourself. If evaluation fails, the working program continues while you repair the draft.

Only main.lisp and editor.lisp are entry files. New projects open these two tabs. These two filenames are protected; all other source files are ordinary modules that can be renamed or deleted after updating their imports. The generator widget imports its recipes like any other component. Older projects retain scene, audio and UI files through explicit imports, preserving their code without requiring those filenames.

Asset previews

Click an image resource to open its WebGPU preview. Drag inside the checkerboard to pan; use the mouse wheel to zoom around the pointer. The +/- controls zoom around the center; Fit resets pan/zoom and fits large images to the viewport without enlarging small ones. 1:1 displays one image pixel per screen pixel. Transparency shows through the checkerboard. Previewing never modifies the asset.

Click an audio resource to decode it with the browser's supported audio formats. The waveform preserves peaks across channels. Play/Pause resumes from the current position; Stop returns to the beginning. Click or drag the waveform to seek. The playhead and elapsed time update during playback. Closing the window, Escape, or switching to another widget stops asset playback. Preview playback is independent of procedural generator controls. A decode error appears inside the window and leaves the editor usable.

Import resolution

; main.lisp
(import "./lib/movement.lisp")
(defn update [dt]
  (move-player dt))
; lib/movement.lisp
(import "../lib/math.lisp")
(defn move-player [dt]
  (set! :x (+ (get :x) (twice dt))))
; lib/math.lisp
(defn twice [value] (* value 2))

import is a top-level form with one literal string. Paths resolve relative to the importing file. A leading slash resolves from the project root: (import "/lib/math.lisp"). Include the extension; there is no extension guessing, package search, or network fetch. Normalization accepts . and .. but rejects paths that escape the project, URLs and Windows paths.

Dependencies load first, once per evaluation, in import order. Missing files and cycles report the affected paths. Imported CPU definitions share one global environment; there are no namespaces or automatic exports, so choose distinct function names. Only files reachable from an entry are loaded automatically. An unused library or command file is retained in the project without being executed.

Application lifecycle hooks

; main.lisp: CPU and GPU code can share a file.
(init! :radius 20)

; Optional CPU update hook, in seconds, while unpaused.
(defn update [dt]
  (set! :radius (clamp (+ (get :radius) dt) 20 60)))

; Required render hook: compiled into a WebGPU fragment program.
(defpixel render [p time]
  (background "#101613")
  (fill "#bbd6a6")
  (circle [160 120] (param :radius)))

Without an active scene, the main import graph must define exactly one defpixel render. It can live in an imported file; the filename has no special meaning. Only this hook compiles to the scene shader. CPU forms run normally. p is the pixel position and time is elapsed game time. Pass shared state to the GPU through param. The shader subset applies inside the render hook.

Optional (defn init [] ...) runs on initial project activation, import and reset. Optional (defn reload [] ...) runs when live edits are accepted. update [dt] receives a zero-duration validation call and then a call each unpaused frame. Use top-level init! for state that should survive live edits. Optional (defn sound [] ...) produces gameplay audio; without it, audio is silent. These functions can be defined anywhere reachable from the entry points. The editor's CPU drawing hook remains (defn editor [] ...).

Version 5 saves require only the two entry files. Older projects automatically gain explicit imports for their previous scene/audio/UI modules. Legacy scene updates are called from an update wrapper; the existing pixel hook becomes render. Version 4 projects rename their application entry from game.lisp to main.lisp. Customized legacy modules are kept. Unreferenced files do not execute, and version 5 loading does not recreate deleted modules.

Swappable scene resources

; main.lisp: application entry point
(start-scene "scenes/menu.scene.lisp")

; Later, from an update function or command:
(start-scene "scenes/level-one.scene.lisp")
; scenes/menu.scene.lisp
(init! :menu-time 0)
(defn enter [] (set! :menu-time 0))
(defn update [dt]
  (set! :menu-time (+ (get :menu-time) dt)))
(defn exit [] (set! :menu-time 0))
(defpixel render [p time]
  (background "#101613")
  (fill "#bbd6a6")
  (circle [160 120] (+ 20 (* 4 (sin time)))))

Scenes use .scene.lisp (recommended) or .scene. Paths passed to start-scene resolve from the project root. Each scene has its own function environment and imports, so scenes can reuse hook names without replacing application or editor functions. Shared project state is accessible with get/set!; choose distinct state keys or clear scene-specific state in exit. Application helpers are available in scenes; scene functions stay private to their scene.

The outgoing scene's exit [] precedes the incoming scene's init [] and enter []. An active scene's update [dt] runs after the application update, and its required defpixel render becomes the preview's WebGPU pipeline. Live edits call reload [] while retaining state. Optional scene sound [] supplies audio; otherwise application audio is used. Shader time starts at zero on scene entry. The selected scene is saved with the project.

Transitions stage state, lifecycle hooks and GPU compilation before committing. Failed transitions leave the current scene running. Browser actions requested by lifecycle hooks run after acceptance. An unselected scene file does not execute. Main may also render directly without scenes; (start-scene "") leaves the active scene and uses main's render hook. (active-scene) returns the active path or an empty string. The editor continues running across scene changes.

Image and audio generators

Open either generator from View → Image generator / Audio generator. Each window combines its own editable source, preview, and GUI controls. Changes evaluate live with the project. The image generator uses generators/image.lisp, with its own WebGPU texture and exactly one defpixel. Its preview is 320 × 240 at time zero and does not replace the game shader. The stock recipe draws a circle, square or line; change position, radius and color with the GUI, or rewrite the hook for a more elaborate image. GUI parameters matter only when your recipe reads them.

The audio generator uses generators/audio.lisp and (defn generate-sound [] ...). It mixes voice calls like the gameplay audio patch, with independent waveform, start/end frequency, duration and gain controls. Play auditions the current buffer. Waveform previews and exports use that same generated buffer. Its :sound-* parameters are separate from gameplay sound settings.

Keep stores an image or audio asset in the project. PNG or WAV stores it and downloads it. Default paths are assets/generated.png and assets/generated.wav; repeated generation replaces those assets. Custom paths are available through the Lisp APIs below. Existing imported assets are stored and downloadable; direct gameplay sampling of arbitrary imported images/audio is not yet exposed.

Command palette

Open Commands, Project → Command palette, or Ctrl/Cmd+Shift+P. Type part of a path to filter saved commands under commands/, then click a result to execute it. Or type a Lisp program and press Run Lisp or Ctrl/Cmd+Enter. Palette text is transient: it is not saved as a project file and is never evaluated just because you type it. 

; A command can automate state changes and exports.
(set! :x 160)
(set! :y 190)
(set! :vy 0)
(export-image "assets/portrait.png")
(export-sound "assets/chime.wav")

Create a file such as commands/reset-player.lisp to add your own saved command. Click the small play button beside its explorer icon to run it without opening a code tab, or choose Run command from its right-click menu. Nested command folders work too. These programs run explicitly rather than during normal live evaluation. Commands share the active CPU functions and state and can import helpers relative to commands/. Typed programs resolve imports as though they are in that directory too. Use set! for immediate state edits, or reset-project to rebuild all state from defaults.

Each loaded module uses the normal evaluation budget. Execution is sequential: effects before an error remain. Browser file/audio actions are deferred until the command finishes its synchronous forms, and report errors in the status bar. Drawing primitives belong inside editor or pixel hooks; commands should call services and change state.

Keeping the current editor

Unmodified bundled editor components upgrade automatically when a saved project loads. Customized components keep their source; use the recovery shell to adopt the latest widgets.

F2 opens the latest recovery shell without replacing your project’s editor source. Creating or renaming files, editing gameplay or generators, and resetting state keep that shell active, including after reload. Accepting an edit to editor.lisp or ui/components.lisp returns to the project editor.

In recovery, Use latest editor adopts the bundled editor and widget library permanently. Changed project sources are kept as editor-backup-1.lisp and ui-backup-1.lisp (with increasing numbers if needed). The control appears in Project on every screen. View → Project editor explicitly leaves recovery without upgrading.

Custom editors can use (recovery?), (upgrade-editor), and (leave-recovery). Recovery mode is saved with the project, while recognized unmodified stock source is upgraded by content even if the project already uses version 3.

File pane APIs

(project-tree) returns up to 64 visible rows beginning at the clamped :file-offset. Each row is [path kind buffer-key basename depth expanded asset-kind]. Kind is folder, lisp or asset; asset-kind is folder, code, image, audio or asset. MIME metadata and filename extensions identify imported assets. (project-tree-count) counts visible rows and (project-tree-offset) returns the viewport-clamped offset. (toggle-folder path) changes expansion and resets scrolling; expansion is a JSON string in :open-folders. Set :show-files to toggle the pane.

(resource-region path kind asset-kind origin size) registers a tree row for pointer, keyboard and context menu input. Icons, nesting, scrolling and menus are painted by Lisp. Filename dialogs use :window "file-path" and the transient __path buffer. Names beginning with __ are reserved for input buffers.

Project format and persistence

Version 3 JSON has files (named source strings), resources (MIME type and base64 data URL per asset), and state. Source drafts are included in a manual Save project; automatic browser persistence retains accepted source. Resource changes are saved with the project. v1/v2 saves migrate without losing custom source or state; stock editor/widget definitions receive the new tools. F2 opens the latest recovery shell if a custom editor has no controls for them.

Limits are 256 source files, 100,000 characters per source, 256 assets, and 6 MB per imported/generated asset; project imports allow 16 MB total. Browser-local storage has its own quota. If a large project exceeds it, use Save project to preserve it as JSON. Five entry names are currently fixed; additional files are unlimited in role within the stated file count. All source and assets are project data, so GitHub Pages hosting still requires only static repository files.
